# План: призы, доступ и награды турниров

## Текущее состояние

Часть данных турнира уже управляется из админки:

- название, slug, описание;
- даты начала и окончания;
- статус публикации;
- изображения и иконка турнира;
- разрешенные виды спорта;
- минимальный коэффициент;
- тип прогноза;
- минимальная уверенность;
- минимум прогнозов и выигранных прогнозов для допуска;
- текстовые условия участия;
- текстовые правила формата;
- этапы турнира;
- достижения турнира;
- денежные призы за 1, 2 и 3 место.

Часть данных сейчас зашита в отображении или собирается fallback-логикой:

- VIP-бонусы за места;
- дополнительные коины;
- бонусы за 4 и 5 место;
- подписи типа `VIP на 3 месяца`;
- блоки преимуществ победителя;
- условия закрытого доступа;
- платность участия;
- проверка подписчиков, лайков, побед в турнирах;
- отображение персонального допуска пользователя.

Цель: сделать турниры полностью управляемыми из админки и красиво показывать эти правила на внутренних страницах.

## 1. Модель призов турнира

Добавить модель `TournamentPrize`.

Поля:

- `tournament` - связь с турниром;
- `place` - место в рейтинге;
- `money_amount` - денежный приз;
- `coins_amount` - коины на виртуальный счет;
- `vip_days` - количество дней VIP;
- `achievement` - достижение, которое выдается за место;
- `title` - название награды;
- `description` - описание награды;
- `sort_order` - порядок отображения;
- `is_active` - показывать/учитывать приз.

Зачем:

- не ограничиваться только 1, 2 и 3 местом;
- задавать 4, 5, 10 мест из админки;
- добавлять деньги, коины, VIP и достижения в любой комбинации;
- убрать hardcode из вкладки `Призы`.

## 2. Админка призов

В `TournamentAdmin` добавить inline `TournamentPrizeInline`.

Внутри турнира админ должен задавать:

- место;
- деньги;
- коины;
- VIP-дни;
- достижение;
- название и описание бонуса;
- активность;
- порядок.

Старые поля `prize_first`, `prize_second`, `prize_third` можно оставить временно для совместимости, но новые страницы должны читать призы из `TournamentPrize`.

## 3. Миграция старых призов

Создать data migration:

- `prize_first` -> `TournamentPrize(place=1)`;
- `prize_second` -> `TournamentPrize(place=2)`;
- `prize_third` -> `TournamentPrize(place=3)`.

Если приз уже создан вручную, миграция не должна дублировать его.

После стабилизации можно будет убрать старые поля отдельной задачей.

## 4. Тип доступа турнира

В `Tournament` добавить поля:

- `access_type`:
  - `open` - открытый;
  - `closed` - закрытый.
- `entry_type`:
  - `free` - бесплатный;
  - `paid` - платный.
- `entry_fee_coins` - стоимость участия в коинах.
- `analysts_only` - только капперы.
- `vip_only` - только VIP.
- `new_users_only` - только новые пользователи.

На карточках и внутренней странице показывать бейджи:

- `Открытый турнир`;
- `Закрытый турнир`;
- `Только VIP`;
- `Только новые пользователи`;
- `Вход: 500 коинов`;
- `Только капперы`.

## 5. Гибкие условия допуска

Добавить модель `TournamentEligibilityRule`.

Поля:

- `tournament` - турнир;
- `rule_type` - тип условия;
- `operator` - оператор сравнения;
- `value` - числовое значение;
- `sport` - спорт, если условие зависит от спорта;
- `title` - понятное название условия;
- `description` - пояснение;
- `sort_order` - порядок;
- `is_active` - активно ли условие.

Типы условий:

- `vip_status` - нужен VIP;
- `new_user` - только новый пользователь;
- `tournament_wins` - количество выигранных турниров;
- `predictions_count` - количество опубликованных прогнозов;
- `winning_predictions_count` - количество выигранных прогнозов;
- `followers_count` - количество подписчиков;
- `likes_count` - количество лайков;
- `live_predictions_count` - количество live-прогнозов;
- `custom_metric` - резерв для будущих метрик.

Операторы:

- `gte` - больше или равно;
- `lte` - меньше или равно;
- `eq` - равно.

Примеры условий:

- VIP-статус обязателен;
- пользователь выиграл хотя бы 1 турнир;
- пользователь выиграл минимум 3 турнира;
- минимум 50 подписчиков;
- минимум 200 лайков;
- минимум 20 выигранных прогнозов по хоккею;
- минимум 50 подписчиков и 200 лайков одновременно.

## 6. Логика объединения условий

В `Tournament` добавить поле `eligibility_mode`:

- `all` - пользователь должен выполнить все условия;
- `any` - достаточно выполнить одно условие.

Для сложных сценариев сначала хватит режима `all`.

Пример:

- VIP only + выиграл 1 турнир = оба условия обязательны.
- 50 подписчиков + 200 лайков = оба условия обязательны.

Если позже понадобится логика групп, можно добавить `group_key` в `TournamentEligibilityRule`.

## 7. Сервис проверки допуска

Создать сервис:

`tournaments/services/eligibility.py`

Основная функция:

`check_tournament_eligibility(user, tournament)`

Она должна возвращать структуру:

- `allowed` - может ли участвовать;
- `reasons` - причины отказа;
- `rules` - список условий с прогрессом;
- `entry_fee_coins` - стоимость входа;
- `has_enough_coins` - хватает ли коинов.

Пример результата:

```python
{
    "allowed": False,
    "rules": [
        {
            "title": "VIP-статус",
            "required": True,
            "current": False,
            "passed": False,
        },
        {
            "title": "Подписчики",
            "required": 50,
            "current": 43,
            "passed": False,
        },
        {
            "title": "Лайки",
            "required": 200,
            "current": 180,
            "passed": False,
        },
    ],
    "reasons": [
        "Нужен VIP-статус",
        "Не хватает 7 подписчиков",
        "Не хватает 20 лайков",
    ],
}
```

## 8. Обновить вступление в турнир

В `tournaments/services/join.py` перед созданием участия:

1. Проверять дату турнира.
2. Проверять, что пользователь может участвовать.
3. Проверять условия допуска.
4. Если турнир платный, проверять баланс коинов.
5. Списывать коины за участие.
6. Создавать `TournamentParticipant`.
7. Записывать transaction/log, чтобы списание не повторилось.

Нужна защита от повторного списания при двойном клике.

## 9. Платные турниры

Для платных турниров:

- участие списывает коины с виртуального счета;
- в админке задается `entry_fee_coins`;
- на странице показывается цена участия;
- кнопка участия показывает:
  - `Участвовать за 500 коинов`;
  - если коинов не хватает: `Недостаточно коинов`.

В wallet добавить отдельный тип операции:

- `tournament_entry_fee`;
- `tournament_prize_coins`;

## 10. Выдача наград

Создать сервис:

`tournaments/services/rewards.py`

Функция:

`award_tournament_prizes(tournament)`

Она должна:

1. Найти финальные результаты.
2. Для каждого места найти `TournamentPrize`.
3. Начислить деньги.
4. Начислить коины.
5. Выдать VIP на нужное количество дней.
6. Выдать достижение.
7. Записать факт выдачи.

Нужно добавить модель или поля для idempotency:

- `TournamentPrizeAward`;
- `tournament`;
- `participant`;
- `prize`;
- `money_awarded`;
- `coins_awarded`;
- `vip_days_awarded`;
- `achievement_awarded`;
- `created_at`.

Это защитит от повторной выдачи призов.

## 11. Отображение на вкладке `Главная`

Добавить красивый блок условий участия.

Содержимое:

- тип турнира: открытый/закрытый;
- стоимость участия;
- список условий допуска;
- персональный статус пользователя.

Примеры строк:

- `VIP-статус` - выполнено / не выполнено;
- `Подписчики` - `43 / 50`;
- `Лайки` - `180 / 200`;
- `Победы в турнирах` - `1 / 3`;
- `Прогнозы по хоккею` - `16 / 20`;
- `Коины для входа` - `350 / 500`.

Если пользователь не авторизован, показывать условия без персонального прогресса.

## 12. Отображение на вкладке `Призы`

Вкладка `Призы` должна читать только `TournamentPrize`.

Таблица:

- место;
- денежный приз;
- коины;
- VIP;
- достижение;
- бонус/описание.

Карточка справа:

- награда за 1 место;
- сумма денег;
- коины;
- VIP;
- достижение;
- дополнительные преимущества.

Нижний блок:

- срок выплаты;
- куда начисляются деньги;
- куда начисляются коины;
- условия попадания в призовую зону.

Тексты нижнего блока можно вынести в поля турнира:

- `reward_payout_text`;
- `reward_wallet_text`;
- `reward_rules_text`.

## 13. Отображение на вкладке `О турнире`

## 18. Важные решения перед разработкой

Нужно отдельно решить:

- что считать новым пользователем;
- по какой модели считать лайки;
- учитывать ли лайки только на прогнозах или на всех сущностях;
- какие победы в турнирах считать: все или только завершенные с призовым местом;
- как списывать коины за платный турнир при выходе из турнира;
- возвращать ли коины, если турнир отменен;
- можно ли участвовать не-капперам;
- могут ли VIP-дни суммироваться с текущим VIP;
- в какой wallet начислять денежные призы и коины.
