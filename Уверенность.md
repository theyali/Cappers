Определить правила расчета

Берем только опубликованные купоны.
Берем только рассчитанные купоны: win / lose.
refund исключаем из процента попадания, но можно показывать отдельно.
Группируем по confidence.
Для каждого уровня считаем:
сколько купонов было;
сколько выиграло;
реальный процент прохода;
разницу между заявленной уверенностью и фактом.
Пример:
confidence=80, купонов 50, выиграло 27 → реальный проход 54%.

Сгладить confidence по бакетам
Не показывал бы каждое значение от 1 до 100, это будет шумно.

Лучше бакеты:

0-49%
50-59%
60-69%
70-79%
80-89%
90-100%
Тогда метрика будет устойчивее:
“Когда каппер ставит 80-89%, реально заходит 54%”.

Добавить общую оценку калибровки
Помимо таблицы, я бы добавил один понятный показатель:

“Точность уверенности”
или “Отклонение уверенности”
Например:
каппер в среднем завышает уверенность на 18%.

Формула простая:
средняя абсолютная разница между заявленной уверенностью и фактическим проходом по бакетам, с учетом количества купонов.

Порог достоверности
Не показывать бакеты, где мало данных.

Например:

меньше 5 купонов → “Недостаточно данных”
5-19 купонов → показывать, но с пометкой “малая выборка”
20+ купонов → полноценная метрика
Где показывать
Я бы добавил в 3 места:

На странице каппера: публичный блок “Калибровка уверенности”.
В кабинете каппера: расширенный блок с деталями.
В статистике капперов: короткий показатель, например “Отклонение: -12%”.
UI
Лучший формат:

небольшая таблица по бакетам;
горизонтальные бары:
заявлено: 80-89%
реально: 54%
цвет:
зеленый, если факт близко к заявке;
желтый, если отклонение среднее;
красный, если каппер системно завышает уверенность.
Тесты
Добавить тесты:

выигрыш/проигрыш считаются;
pending/refund не ломают расчет;
бакеты работают правильно;
малая выборка помечается;
публичная страница каппера показывает метрику.
