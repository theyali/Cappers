План

    1
Спроектировать модель индекса

Цель: один публичный индекс доверия каппера `trust_index` от `0.0` до `10.0`.
Индекс считается по опубликованным прогнозам каппера и хранится готовым числом с одним знаком после точки: `9.7`, `5.5`, `5.0`, максимум `10.0`.

Базовые данные:
- берем только `PredictionCoupon` со статусом `published`;
- для результативной статистики берем купоны со статусами `win`, `lose`, `refund`;
- прибыль купона:
  - `win`: `possible_payout - total_stake`;
  - `lose`: `-total_stake`;
  - `refund`: `0`;
- общий коэффициент купона: `possible_payout / total_stake`, если `total_stake > 0`;
- дата результата: `settled_at`, если есть, иначе `updated_at`.

Финальная формула:

`trust_index = round_to_1_decimal(sum(component_score * component_weight / 10))`

Каждый `component_score` считается от `0` до `10`.
Сумма весов равна `10`, поэтому итог тоже получается от `0.0` до `10.0`.

Веса компонентов:
- ROI: вес `2.2`;
- дистанция прогнозов: вес `1.5`;
- максимальная просадка: вес `1.3`;
- стабильность: вес `1.2`;
- средний коэффициент: вес `0.8`;
- частота прогнозов: вес `1.0`;
- совпадение уверенности с результатом: вес `2.0`.

1. ROI score

ROI считается по всем опубликованным рассчитанным купонам:

`roi = total_profit / total_stake * 100`

Шкала:
- `roi <= -20%` -> `0`;
- `-10%` -> `2`;
- `0%` -> `4`;
- `10%` -> `6`;
- `20%` -> `8`;
- `>= 35%` -> `10`.

Между точками используется линейная интерполяция.

2. Distance score

Дистанция нужна, чтобы не давать высокий индекс за маленькую выборку.

`distance_score = min(10, sqrt(settled_coupons_count / 100) * 10)`

Примеры:
- `1` рассчитанный прогноз -> около `1.0`;
- `25` -> `5.0`;
- `50` -> около `7.1`;
- `100+` -> `10.0`.

3. Drawdown score

Максимальная просадка считается по кривой накопленной прибыли, отсортированной по дате результата.

`max_drawdown_percent = max_drawdown / total_stake * 100`

Шкала:
- `<= 5%` -> `10`;
- `10%` -> `8`;
- `20%` -> `5`;
- `35%` -> `2`;
- `>= 50%` -> `0`.

Между точками используется линейная интерполяция.

4. Stability score

Стабильность считается по активным месяцам, где есть минимум `3` рассчитанных прогноза.

Берем:
- `monthly_roi_stddev` - разброс месячного ROI;
- `positive_month_share` - доля месяцев с положительной прибылью.

Формула:

`stability_score = stddev_score * 0.7 + positive_month_score * 0.3`

Где:
- `stddev_score = clamp(10 - monthly_roi_stddev / 6, 0, 10)`;
- `positive_month_score = positive_month_share * 10`.

Если активных месяцев меньше `2`, ставим нейтральный `stability_score = 5.0`.
Малую историю дополнительно ограничивает `distance_score`.

5. Average coefficient score

Средний коэффициент должен учитывать риск. Очень низкие коэффициенты почти не дают ценности, очень высокие чаще означают лотерею.

Шкала:
- `1.60-2.40` -> `10`;
- `1.40-1.59` или `2.41-3.00` -> `8`;
- `1.20-1.39` или `3.01-4.00` -> `5`;
- `1.01-1.19` или `4.01-6.00` -> `2`;
- `<= 1.00` или `> 6.00` -> `0`.

6. Frequency score

Частота считается по опубликованным прогнозам за последние `30` дней.

Шкала:
- `0` прогнозов -> `0`;
- `1` -> `2`;
- `4` -> `5`;
- `8` -> `8`;
- `12+` -> `10`.

Между точками используется линейная интерполяция.

7. Confidence calibration score

Используем уже существующую логику калибровки уверенности:
сравниваем заявленную уверенность каппера с фактическим процентом выигрышей по бакетам.

Берем `average_abs_error` в процентных пунктах.

Шкала:
- `0-5 п.п.` ошибки -> `10`;
- `15 п.п.` -> `6`;
- `30+ п.п.` -> `0`.

Между точками используется линейная интерполяция.
Если данных по уверенности нет, ставим нейтральный `5.0`.

Потолки для маленькой выборки:
- `0` рассчитанных прогнозов -> итоговый `trust_index = 0.0`;
- `1-4` рассчитанных прогноза -> максимум `4.0`;
- `5-19` рассчитанных прогнозов -> максимум `6.0`;
- `20-49` рассчитанных прогнозов -> максимум `8.0`;
- `50+` рассчитанных прогнозов -> без дополнительного потолка.

Уровни индекса для будущей аватарки:
- `8.5-10.0` -> высокий уровень;
- `7.0-8.4` -> хороший уровень;
- `5.0-6.9` -> средний уровень;
- `0.1-4.9` -> низкий уровень;
- `0.0` -> нет надежной истории.

    2
Добавить хранение в базу

Индекс хранится в `cabinet.AnalystProfile`, потому что он относится к публичному профилю каппера и должен быстро читаться на карточках, аватарках, в таблицах и профиле.

Добавленные поля:
- `trust_index` - готовый индекс доверия от `0.0` до `10.0`;
- `trust_index_updated_at` - дата и время последнего пересчета.

Параметры хранения:
- `trust_index`: `DecimalField(max_digits=3, decimal_places=1, default=0, db_index=True)`;
- валидаторы: минимум `0`, максимум `10`;
- `trust_index_updated_at`: nullable `DateTimeField`, `db_index=True`;
- поле показывается в админке, но не редактируется вручную, потому что значение должен обновлять единый сервис расчета.

Миграция: `cabinet/migrations/0023_analystprofile_trust_index_and_more.py`.

    3
Сделать единый сервис расчета

Сервис реализован в `cabinet/trust_index.py`.

Публичный API:
- `CapperTrustIndexService(analyst_id).calculate()` - считает индекс, компоненты и технические метрики без записи в базу;
- `CapperTrustIndexService(analyst_id).refresh()` - считает индекс и сохраняет его в `AnalystProfile`;
- `calculate_capper_trust_index(analyst_id)` - короткий helper для расчета;
- `refresh_capper_trust_index(analyst_id)` - короткий helper для пересчета и сохранения.

Что считает сервис:
- `trust_index` с округлением до одного знака;
- компоненты `roi`, `distance`, `drawdown`, `stability`, `avg_coefficient`, `frequency`, `confidence`;
- технические метрики: дистанция, ROI, банк, прибыль, просадка, средний кф, ошибка уверенности.

Автоматический пересчет:
- подключен в `cabinet/signals.py` после сохранения `PredictionCoupon`;
- при смене автора обновляется новый и предыдущий каппер;
- после удаления купона индекс пересчитывается заново;
- запись в `AnalystProfile` выполняется через `update()`, чтобы не запускать лишние profile-сигналы.

Массовый пересчет:
- добавлена команда `python manage.py refresh_trust_indexes`;
- можно пересчитать всех капперов;
- можно передать конкретные `analyst_ids`;
- есть опция `--limit` для батчей/cron.

Тесты:
- добавлен модуль `cabinet/test_trust_index.py`;
- проверяет нулевую историю, потолок маленькой выборки, сохранение в профиль, signal refresh и нейтральную стабильность при малой истории.
