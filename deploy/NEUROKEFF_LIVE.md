# Neurokeff: live WebSocket + REST fallback

Документация протокола: https://sports.api-neurokeff.ru/api/docs/websockets

Серверный процесс `run_neurokeff_live` подключается к `/ws/v1/live/` с существующим
`NEUROKEFF_API_TOKEN` в заголовке `Authorization: Token …`. Токен не передаётся
в браузер и не записывается в логи подключения. Фильтр `sport` содержит PK видов
спорта из `NEUROKEFF_SPORTS`, либо из `NEUROKEFF_LIVE_WS_SPORTS`.

REST live-задачи четырёх видов спорта остаются страховкой и запускаются раз в
минуту. Расписания/сервисы статистики, событий и коэффициентов не изменены.
Существующие запросы фронтенда к нашему Django также остаются: это не запросы к
Neurokeff. WebSocket используется между нашим сервером и поставщиком.

## Приоритет источников

После валидного snapshot каждый обновлённый через WS матч помечается ID сессии.
Пока эта сессия подтверждает соединение, REST не перезаписывает счёт, статус,
таймер, периоды, point и подачу этого матча — даже если REST-запрос начался позже
WS-обновления. Это относится также к REST finished/prematch и точечным проверкам:
они не могут обойти приоритет активного WS-матча. Остальные данные и существующие
синхронизаторы статистики, событий и коэффициентов работают как раньше.

Сессия объявляется готовой только после проверки первого snapshot. Независимый
heartbeat раз в 10 секунд посылает protocol ping и ждёт pong до 5 секунд. Только
подтверждённый pong продлевает приоритет в общем кэше на 30 секунд. При разрыве,
ошибке обработки или остановке consumer приоритет снимается сразу; после жёсткого
падения процесса он исчезнет по TTL. При недоступном кэше используется REST fallback.
Если соединение отвечает на ping, но 90 секунд не приходит ни одного сообщения
с состоянием матчей, consumer снимает приоритет и переподключается за новым snapshot.

Матчи вне подписки/потока по-прежнему обновляются REST. Исчезновение из snapshot,
`match.removed` и статус `2` разрешают точечную REST-сверку. Поздняя задача не сможет
затереть матч, который уже снова вошёл в live и получил WS-приоритет. После reconnect
новый snapshot забирает управление обратно, даже если локальная дата последнего
REST-запроса новее времени snapshot. Дубликаты внутри сессии по-прежнему отбрасываются.

## Включение

Необязательные параметры `.env` (значения URL и фильтра по умолчанию уже в коде):

```dotenv
NEUROKEFF_LIVE_WS_URL=wss://sports.api-neurokeff.ru/ws/v1/live/
# Только разрешённые подпиской PK; пусто = NEUROKEFF_SPORTS.
NEUROKEFF_LIVE_WS_SPORTS=
```

Сначала собрать образы, применить миграции и перезапустить обычные worker/beat:

```sh
docker compose build
docker compose run --rm migrate
docker compose up -d web celery celery-beat
docker compose exec -T web python manage.py run_neurokeff_live --check
docker compose --profile live up -d --build neurokeff-live
docker compose --profile live logs --tail=50 -f neurokeff-live
```

`--check` проверяет подключение и схему первого snapshot **без записей в БД**.
Нужен активный Celery worker: обнаруженные неизвестные матчи и пропуски snapshot
сверяются точечными запросами `games/info`, без синхронизации stats/events/odds.
Для деплоя штатным скриптом: `DEPLOY_LIVE_WS=1 bash deploy/deploy.sh`.
Остановка только потока: `docker compose --profile live stop neurokeff-live`.

Перезапуск beat загружает минутное расписание из settings. Если в админке Celery
созданы дополнительные live-задачи с другими именами, их нужно отдельно отключить
или перевести на минуту, чтобы не осталось дублирующего частого REST polling.

## Обработка данных

- `game_pk` сопоставляется с `Match.external_id`: здесь уже хранится REST `Game.id`,
  не внешний ID исходного спортивного поставщика. Проверяются PK спорта и команд.
- `live.snapshot` применяется при каждом подключении, затем полные `match.updated`,
  `match.entered_live` и `match.status_changed`; поле `changed` не является patch.
- Сохраняются счёт, статус, clock, текущий период, счёт периодов, point и подача.
  Полный исходный объект сохраняется в `raw_data.live_stream.match`.
- Дубликаты и запоздавшие сообщения отбрасываются по времени сообщения; UUID
  `event_id` не используется как последовательность. Запоздавший REST не затирает
  более новое WS-состояние, завершённые игры не возвращаются в live.
- Статус `2` — потеря связи со скаутом: отдельный `connection_lost`, не завершение
  и не основание для автоматического возврата ставок. `match.removed` переводит
  live в это состояние и запрашивает REST-проверку. Отсутствие в snapshot только
  запрашивает проверку. Ни один из этих сигналов не удаляет матч.
- Прошедшее время начала prematch-матча больше не переводит его в live автоматически:
  вместо этого ставится флаг для точечной REST-проверки текущего статуса.
- Нет финального счёта — старый live-счёт не используется как финальный.
  Расчёт ставок остаётся за существующими задачами, не выполняется в WS-процессе.
- Protocol ping/pong проверяет соединение; reconnect с задержкой до 30 секунд.
  После reconnect приходит новый snapshot, replay событий не гарантируется.
- Redis lease допускает только одного consumer для проекта, продлевается
  независимо от обработки snapshot. Ошибки 4401/4403, HTTP 401/403 останавливают
  команду с понятной ошибкой; проверьте токен и доступные подписке виды спорта.

WebSocket не является источником истины поверх неверных данных поставщика.
Если сам Neurokeff продолжает отдавать статус `1`, завершение не выдумывается по
давности матча или последнему событию. Уже застрявшие записи сверяются через
snapshot и существующую задачу `sync_stuck_live_matches`.
