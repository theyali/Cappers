## 3. Пункт 19: застрявшие игры без счета не должны превращать прогнозы в проигрыш

Цель: если матч завершен/застрял, но счета нет или счет невозможно распарсить, прогнозы должны публично оставаться “В ожидании”. Такие матчи должны попадать в отдельную страницу админки для ручной проверки.

### 3.1. Текущая логика

Файл: `game/services/settlement.py`

Сейчас:

- `settle_finished_matches()` берет только `Match.SyncScope.FINISHED` и `.exclude(score="")`.
- `resolve_match_bets()` возвращает `None`, если `_parse_score(match.score)` не смог распарсить счет.
- `prediction_state()` по неизвестному рынку возвращает `LOSE`.

Проблемный риск:

- если матч формально finished, но счет пустой/битый, он не должен рассчитать позиции;
- если рынок не распознан, нельзя автоматически ставить `LOSE`, лучше оставить позицию пустой и купон pending.

### 3.2. Добавить модель ручной проверки матчей

Файл: `game/models.py`

Добавить модель:

```python
class MatchManualReview(models.Model):
    class Reason(models.TextChoices):
        MISSING_SCORE = "missing_score", "Нет счета"
        INVALID_SCORE = "invalid_score", "Некорректный счет"
        UNKNOWN_MARKET = "unknown_market", "Неизвестный рынок прогноза"
        SETTLEMENT_ERROR = "settlement_error", "Ошибка расчета"

    class Status(models.TextChoices):
        OPEN = "open", "Открыта"
        RESOLVED = "resolved", "Решена"
        IGNORED = "ignored", "Игнорировать"

    match = models.ForeignKey(Match, on_delete=models.CASCADE, related_name="manual_reviews")
    reason = models.CharField(max_length=32, choices=Reason.choices, db_index=True)
    status = models.CharField(max_length=16, choices=Status.choices, default=Status.OPEN, db_index=True)
    details = models.JSONField(default=dict, blank=True)
    created_at = models.DateTimeField(auto_now_add=True)
    updated_at = models.DateTimeField(auto_now=True)
    resolved_at = models.DateTimeField(null=True, blank=True)

    class Meta:
        constraints = [
            models.UniqueConstraint(
                fields=["match", "reason", "status"],
                name="unique_open_match_review_reason",
            )
        ]
        indexes = [
            models.Index(fields=["status", "reason", "created_at"]),
            models.Index(fields=["match", "status"]),
        ]
```

Важное замечание: уникальность по `status` позволит иметь одну открытую запись на причину. Если нужно хранить историю, можно вместо этого добавить условный `UniqueConstraint(condition=Q(status="open"))`.

### 3.5. Не рассчитывать матч без валидного счета

Файл: `game/services/settlement.py`

В `settle_finished_matches()` изменить выборку:

- не ограничиваться `.exclude(score="")`, потому что пустые finished-матчи тоже нужно отправить в ручную проверку;
- брать `Match.SyncScope.FINISHED`;
- внутри цикла:
  - если `not match.score`: создать review `MISSING_SCORE`, `continue`;
  - если `_parse_score(match.score) is None`: создать review `INVALID_SCORE`, `continue`;
  - только потом вызывать `resolve_match_bets(match)`.

Пример:

```python
if not (match.score or "").strip():
    flag_match_for_manual_review(match, MatchManualReview.Reason.MISSING_SCORE, {...})
    continue
if _parse_score(match.score) is None:
    flag_match_for_manual_review(match, MatchManualReview.Reason.INVALID_SCORE, {...})
    continue
```

   - `score="2:1"`;
   - `market="unknown_market"`;
   - ожидание: позиция не lose, купон pending, review `unknown_market`.

4. Валидный обычный рынок все еще считается:
   - winner / total / both_score;
   - ожидание: win/lose/refund как раньше.

## 5. Команды проверки

Минимально:

```bash
python manage.py check
python manage.py test game.test_settlement
python manage.py test cabinet.tests
python manage.py test front.tests
```

Если тесты слишком долгие:

```bash
python manage.py test game.test_settlement game.test_void_match_settlement
python manage.py test cabinet.tests.test_bonus_center
```

Ручная проверка после реализации:

- `/cabinet/register/`:
  - регистрация пользователя;
  - регистрация каппера;
  - выбор спортов;
  - открытие модалки лиг;
  - поиск лиги;
  - сохранение выбранных лиг.
- `/cabinet/profile/`:
  - профиль каппера показывает выбранные спорт/лиги.
- Главная `/`:
  - футер отображается и берет тексты из админки.
- Страницы с `hide_footer=True`:
  - футер не появляется.
- Django admin:
  - редактируются данные футера;
  - видны пользовательские предпочтения;
  - видна страница `MatchManualReview`.
- Settlement:
  - матч без счета не делает прогноз проигрышем;
  - купон остается “В ожидании”;
  - в админке появляется запись ручной проверки.
